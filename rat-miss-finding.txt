        View::share('appearance', $appearance);
        return $next($request);
    }
    // Same for HandleInertiaRequests.php sidebar_state: whitelist ['expanded','collapsed']

    // Optional: limit cookie length max 20 via middleware

[LOW] AF-08 - Inventory Stock Adjustment Race & Negative-Cap
--------------------------------------------------------------------------------
Severity:    LOW | Confidence: MEDIUM | OWASP: A06
Locations:
  app/Repositories/Inventory/InventoryItemRepository.php:120-125  adjustCurrentStock()
  app/Repositories/Pos/PosOrderRepository.php:33  sellableProductsForCheckout() uses lockForUpdate
  app/Services/Pos/PosOrderService.php:95  adjustCurrentStock($product, -quantity) inside transaction

Description:
  adjustCurrentStock():
    public function adjustCurrentStock(InventoryItem $item, float $delta): void {
        $item->current_stock = max(0, (float)$item->current_stock + $delta);
        $item->save(); // NOT locked
    }

  POS checkout PosOrderService.php:56 DB::transaction with sellableProductsForCheckout() that DOES use lockForUpdate for reads, but adjustCurrentStock itself later does separate SELECT + UPDATE without FOR UPDATE. Concurrent voids + checkouts can race:

  T1: read stock 10 -> T2: read stock 10 -> T1: write 9 (10-1) -> T2: write 9 (10-1) => lost update, should be 8

  max(0, ...) prevents negative but hides oversell; two concurrent orders both see 1 left, both succeed writing 0, but should have failed second.

  Impact: Oversell, inventory drift.

  Fix P2:
    // app/Repositories/Inventory/InventoryItemRepository.php
    public function adjustCurrentStock(InventoryItem $item, float $delta): void {
        DB::transaction(function() use ($item, $delta) {
            $fresh = InventoryItem::where('id', $item->id)->lockForUpdate()->firstOrFail();
            $fresh->current_stock = max(0, (float)$fresh->current_stock + $delta);
            $fresh->save();
        });
    }
    // Or use atomic: InventoryItem::where('id',$item->id)->update(['current_stock'=>DB::raw('GREATEST(0, current_stock + '.$delta.')')]);

  Verify:
    Run concurrent php artisan tinker jobs adjusting same item, check final stock equals sum deltas.

  RAT Why Missed: RAT hidden_behavior saw job but not DB race; no concurrency analysis.
