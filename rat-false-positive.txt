RAT Title:       User input reaches dynamic function call
RAT Location:    app/Http/Middleware/HandleAppearance.php:21
RAT Entry:       HandleAppearance
RAT Source:      $request->cookie(
RAT Sink:        dynamic function call
RAT Flow:        HTTP Request -> HandleAppearance -> dynamic function call
RAT Why:         User-controlled input ($request->cookie() reaches dynamic
                 function call in app/Http/Middleware/HandleAppearance.php:21.
                 No clear security boundary was detected.

WHY FALSE POSITIVE:
  Actual code HandleAppearance.php:19:
    View::share('appearance', $request->cookie('appearance') ?? 'system');
  HandleAppearance.php:21 is:
    return $next($request);
  HandleAppearance.php:18 signature: handle(Request $request, Closure(Request):(Response) $next)
  $next is framework Closure, NOT user-controlled function name. No call_user_func,
  no $$var(), no eval. RAT misclassified $next($request) as "dynamic function call".

  Cookie value flows to Blade app.blade.php:10:
    const appearance = '{{ $appearance }}'
  Blade {{ }} escapes via htmlspecialchars ENT_QUOTES ( ' -> &#039; ), so
  even "'><svg onload=alert(1)>" cannot break out. Also app.blade.php:2:
    @class(['dark'=>($appearance??'system')=='dark'])

  Bootstrap: bootstrap/app.php:20 encryptCookies(except: ['appearance','sidebar_state'])
  So cookie is tamperable, but not executable.

REAL RISK: 0/10 (not exploitable). See AF-05 for low hardening: whitelist
  $appearance to ['light','dark','system'] to prevent cache-split.

FIX: Optional hardening HandleAppearance.php:19:
  $appearance = $request->cookie('appearance');
  $appearance = in_array($appearance, ['light','dark','system'], true) ? $appearance : 'system';
  View::share('appearance', $appearance);

COMMAND TO VERIFY:
  php artisan rat:show RAT-001 --no-image
  cat app/Http/Middleware/HandleAppearance.php
